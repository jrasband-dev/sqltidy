sqltidy.dialects.base¶

Base class for SQL dialects.

Each dialect defines its own keywords, data types, functions, and syntax rules.

class sqltidy.dialects.base.SQLDialect[source]¶

Bases: ABC

Base class for SQL dialects.

Each dialect implementation should provide: - name: Unique identifier for the dialect - keywords: Set of SQL keywords specific to this dialect - data_types: Set of data type names - functions: Set of built-in function names - identifier_chars: Special characters allowed in identifiers (e.g., ‘@’ for SQL Server) - quote_chars: Dictionary of quote characters for identifiers and strings - comment_styles: List of comment patterns supported

Initialize the dialect.

abstract property name: str¶

Unique identifier for this dialect (e.g., ‘sqlserver’, ‘postgresql’).

abstract property keywords: Set[str]¶

Set of SQL keywords for this dialect (lowercase).

property data_types: Set[str]¶

Set of data type names (subset of keywords, used for categorization).

property functions: Set[str]¶

Set of built-in function names (subset of keywords).

property identifier_chars: str¶

Special characters allowed in identifiers.

Examples: - SQL Server: ‘@#$’ (for @variables, #temp tables) - PostgreSQL: ‘$’ (for $1, $var) - MySQL: ‘’ (no special chars)

property quote_chars: Dict[str, str]¶

Quote characters for identifiers and strings.

Returns:

Dictionary with ‘identifier’ and ‘string’ keys.

Examples: - SQL Server: {‘identifier’: ‘[’, ‘string’: “’”} - PostgreSQL: {‘identifier’: ‘”’, ‘string’: “’”} - MySQL: {‘identifier’: ‘`’, ‘string’: “’”}

property comment_styles: List[str]¶

List of comment patterns supported by this dialect.

Returns:

List of comment prefixes (e.g., [’–’, ‘#’, ‘/*’])
